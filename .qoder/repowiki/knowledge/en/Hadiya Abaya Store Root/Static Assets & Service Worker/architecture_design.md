Two parallel asset trees are served directly by the hosting layer: `css/` holds the site's stylesheet (`style.css`, ~1900 lines of BEM-named component rules) plus a separate `animations.css` file providing GPU-accelerated keyframes and scroll-reveal utilities; `public/` is the static root containing image assets organized by purpose (`images/banners`, `images/categories`, `images/hero`, `images/products`) and runtime configuration files consumed by the deploy platform — `sw.js` (a custom service worker implementing cache-first for images/static assets and network-first for navigation), `_headers` (Netlify/Vercel-style Cache-Control and security headers), and `_redirects` (SPA fallback to `/index.html`). There is no build step inside this module; CSS variables in `:root` define the design tokens (colors, spacing, typography, z-index scale) that both sheets consume, and the service worker references those same paths so client-side caching stays in sync with the deployed asset layout.
